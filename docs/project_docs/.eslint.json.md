# .eslint.json

This configures ESLint — a static analysis tool that finds and reports problematic patterns in JavaScript/TypeScript code. It enforces code style and catches bugs before runtime.

---

## Line-by-Line Breakdown

```json
"extends": [
  "eslint:recommended",
  "plugin:@typescript-eslint/recommended"
]
```
Inherits two rule sets:
- `eslint:recommended` — ESLint's built-in recommended rules (catches common JS bugs like `no-undef`, `no-unreachable`, `no-dupe-keys`)
- `plugin:@typescript-eslint/recommended` — TypeScript-specific rules (catches TS-specific issues like `no-explicit-any`, `no-unused-vars` with type awareness)

Rules from later entries override earlier ones if they conflict.

```json
"rules": {
```
Custom rule overrides — these take precedence over the inherited rule sets.

```json
  "semi": ["error", "always"]
```
Requires semicolons at the end of every statement. `"error"` means violations fail the lint check. `"always"` means semicolons are mandatory (as opposed to `"never"` for ASI style).

```json
  "quotes": ["error", "single"]
```
Requires single quotes for strings. Double quotes or backticks (when not using template literals) will error.

```json
  "no-unused-vars": "warn"
```
Warns (yellow, doesn't fail) when a variable is declared but never used. Set to `"warn"` instead of `"error"` to avoid blocking development while iterating.

```json
  "@typescript-eslint/explicit-function-return-type": "error"
```
Requires every function to have an explicit return type annotation. Forces you to write `function foo(): string` instead of relying on inference. Improves readability and catches accidental return type changes.
