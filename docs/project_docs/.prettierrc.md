# .prettierrc

This configures Prettier — an opinionated code formatter. Unlike ESLint (which finds problems), Prettier automatically rewrites code to a consistent style.

---

## Line-by-Line Breakdown

```json
"semi": true
```
Add semicolons at the end of statements. Matches the ESLint `"semi": ["error", "always"]` rule.

```json
"trailingComma": "es5"
```
Add trailing commas where valid in ES5 (objects, arrays, function parameters). NOT in function arguments in older syntax. This makes git diffs cleaner — adding a new item to an array only shows one changed line instead of two.

```json
"singleQuote": true
```
Use single quotes for strings. Matches the ESLint `"quotes": ["error", "single"]` rule. JSX will still use double quotes (Prettier's default for JSX).

```json
"printWidth": 80
```
Wrap lines at 80 characters. Prettier will break long lines to stay within this limit. Doesn't apply to strings or comments that can't be broken.

```json
"tabWidth": 2
```
Each indentation level is 2 spaces. Standard for JavaScript/TypeScript projects.

```json
"useTabs": false
```
Indent with spaces, not tab characters. Combined with `tabWidth: 2`, every indent is exactly 2 space characters.

---

## How Prettier and ESLint Work Together

- **Prettier** handles formatting (whitespace, line breaks, quotes, semicolons)
- **ESLint** handles logic/correctness (unused vars, explicit types, no-undef)

They overlap on `semi` and `quotes` — both are configured identically here so they don't conflict. If they disagreed, Prettier would format one way and ESLint would immediately flag it as an error.
